# BryceCast Career Data

This publication folder retains career manifests and reports. The canonical normalized dataset, raw archive, and staging files described below are withheld; see the [data index](../README.md). The detailed ingestion notes below are historical snapshots, not current coverage counts.

Important files:

- `career.dataset.json`: canonical normalized dataset.
- `sources.manifest.json`: source/workstream inventory.
- `staging/`: per-source extracted JSON before normalization.
- `raw/`: fetched raw source artifacts when safe to store.
- `reports/`: validation and coverage reports.
- `reports/ingestion-summary.json`: generated rollup of canonical counts, validation status, source-family import reports, weather/track readiness, and open gaps.
- `reports/career-coverage-matrix.json`: included coverage report. When run with the required corpus, `npm run career:coverage` writes its Markdown companion to `reports/coverage-matrix.md`. The [archived coverage matrix](../../docs/archive/audits/CAREER_ANALYTICS_COVERAGE_MATRIX.md) is a frozen historical snapshot.

Rules:

- Do not put unsupported placeholder rows into the canonical dataset.
- Every result row must have provenance.
- Official source rows should be preserved separately from derived metrics.
- Aggregator rows are cross-checks unless no official row exists.
- Weather rows must not be joined by date alone. They need session, track, timezone/window, source coordinates, distance, and provenance.
- Derived metrics must keep source/calc provenance and should fail validation if they are not traceable.
- Copyrighted article bodies and protected media should not be copied here; store links and short summaries.

Validation:

- Run `npm run career:validate` after every import.
- Run `npm run career:summary` after validation when you need a compact machine-readable status packet for UI work or orchestration.
- Run `npm run career:coverage` after summary when you need the consistency matrix refreshed.
- Warnings are allowed for known incomplete enrichment. Errors mean the dataset is not fit for analytics or UI use.
- The current validator checks event-referenced track coordinates/timezones/layout length and session timezone coverage. Use `reports/validation-report.json` for live coverage because parallel import lanes can add new tracks and sessions between backfill runs.
