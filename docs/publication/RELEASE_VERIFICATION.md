## Integrity corrections during preparation

The subsequent organization pass moved 65 files into the documented folder structure and checked local links across 115 Markdown files. The live contract's new path was propagated through its owning context-pack producer; the full UI package validator, build, and publication tests passed. Frozen historical evidence retains original bytes and can be located through the [path relocation index](../archive/PATHS.md).

Removing raw archives exposed a pre-existing generator issue: the UI package's skip-upstream switch still ran several upstream builders. The switch now guards every upstream refresh, so bounded package assembly can use retained outputs. Live-context hashes were regenerated by their owning producer, then validated through the complete package validator; hashes were not manually overwritten to force a pass.

Three retained generated evidence files preserve their original bytes because their hashes are referenced by other reports. They may contain inert historical local-path metadata. Such strings are not working credentials. Most operational home/host strings were generalized during history filtering.

## Security scan and history

Gitleaks 8.30.1 reviewed 10,492 unique reachable source blobs (4.211 GiB), including 887 decompressed gzip objects; 326 reflog-only blobs; and 469 additional blobs outside refs and reflogs. Blob-level enumeration was required because raw files marked `-diff` are invisible to an ordinary patch scan. The current candidate and its rewritten history were also scanned. No project credential was identified. Public timing identifiers and source hashes were classified as false positives; third-party browser-key and page-token strings in captured HTML were excluded with those raw files from every candidate ref.

The bounded untracked-file review covered publication-relevant source edits, assets, and catalogs. The untracked multi-gigabyte operational archive was not exhaustively scanned and is not included. It requires its own export and scan before any later release.

The private audit retains redacted findings, original-to-public commit mappings, and tool logs. Public documentation intentionally does not reproduce detected candidate strings or original personal Git email identities. A zero-credential finding is a scan result, not proof that disclosure can never expose a vulnerability. Original captures and runtime material remain outside this edition and subject to independent release review.

## Browser interaction evidence

The tested flow was home → last race debrief → Qualifying → One lap (observed eight-lap selector) → whole-session map → Career; mobile home → Races; then Live with its historical/unavailable banner. The real application rendered meaningful historical results and the qualifying map. The README screenshot at the time, a Laguna Seca qualifying map, came from that local snapshot; it was replaced on 2026-09-21 by a [race section map](../evidence/race-section-heat-map.png) of the 2024 Grand Prix of Portland, captured from the local demo build. Private audit screenshots also retain desktop Career and mobile home/Races views. Other browsers, every race, and live production states remain untested in this pass.

## Remaining verification limits

- The website's current production state, credentials, network configuration, collector freshness, and deployed version were not changed or certified.
- Complete historical reproduction needs permissioned source data and its original environment; the default clone demonstrates the UI and selected methods.
- Stored research results were inspected and source-checked; model fitting and every historical ingestion job were not rerun.
- Rights review applies to included derived data and visual assets as well as withheld raw archives.
